# isoPSV v1.1 Release Notes

isoPSV（isotope-labeled paired-spectrum verification）multi-engine competitive validation software v1.1 (2026-10-21 update).

- Multi-engine competitive searching (pFind/pUniFind family + Comet/MaxQuant/MSFragger/Sage/MetaMorpheus and more)
- Two-stage arbitration (spectrum-level competition + paired-isotope verification), eight weighted indicators with locked weights
- Web console (English by default, switchable to Chinese): parameter generation, live log, stop-point resume, result browser
- **Pure prediction mode (new)**: submit STEP 2 with no strategy row and the base identification table feeds the predictors directly; the output `pure_prediction.tsv` is the input table plus one `predict_cosine_<predictor>` column per enabled predictor (observed vs predicted theoretical-spectrum cosine)
- **Four bundled predictor integrations (new)**: pDeep2, pDeep3, AlphaPeptDeep and MS2PIP in the same run; each keeps its own Python environment (pDeep2 3.7/TF1.15, AlphaPeptDeep 3.10/torch, MS2PIP >= 3.11) and only the environment folder needs to be filled (auto-resolved to `python.exe` or `Scripts\python.exe`); one-click detection fills it automatically
- Unified strategy slots (pFind three arms and pUniFind as peer rows, slot letters alphabetical); pFind standard arm; re-score precondition guard
- Bundled demo dataset (PRIDE PXD003236 Chlamydomonas fraction) + reproduction guide; crosstalk-safe Python subprocess environment; pre-check cache
- **Complete installation guide (new)**: official download links and settings for every supported search engine and predictor, the mandatory per-predictor Python environment isolation (3.7/TF1.15, 3.10/torch, >=3.11) with environment-folder auto-resolution, and a step-by-step operation guide — see `docs/installation.md`
- **Predictor-loop hardening (v2.0.155)**: a predictor row with an empty python path is skipped with an explicit message instead of failing as a bare exit 1; pDeep3 with an empty python falls back to the pDeep2 python already proven in the same run (the predictor addon ships both in one environment) and points PDEEP3_ROOT at the sibling pDeep3 folder; on any predictor failure the tails of `run.log` and `predict.txt.driver.log` are echoed into the main log, so the real cause is visible without opening the per-predictor folder
- **Labeled-sample pure-prediction fixes (v2.0.156)**: labeled inputs (e.g. NeuCode) no longer produce silently empty predictor columns - the export stage registers `label_type` in its own subprocess, and the predict-key fallback accepts the label-stripped modification so combined label+ordinary-modification rows match (verified end to end on synthetic labeled rows and consistent with the E. coli NeuCode LL/TL rerun at 93,000/93,000 coverage); NaN cosines are written as empty with a separate NaN count; an LC_CTYPE probe guards UTF-8 sourcing on system R; `docs/installation.md` gains the labeled pure-prediction recipe with a verified four-line NeuCode `label_type` example
- **AlphaPeptDeep batch-crash resilience (v2.0.164)**: mod_sites are pre-validated against peptide length before reaching torch (out-of-range rows are skipped and counted), and `predict_ms2` failures trigger a bisection retry that isolates and drops only the crash rows - together these handle the peptdeep 1.3.1/alphabase 1.1.0 IndexError on a specific short-peptide length band without any code change on the peptdeep side. The pyro-Glu `[Q]/[E]` residue-only site form now also tries terminal compound keys, and the alias table gains the isotope/ionization variant names from the workstation forensic report
- **Upstreamed field patches + robustness pack (v2.0.165)**: the `proteogenomics_annotated_fasta` key officially splits the pg-gate reference library from the search FASTA (the workstation had re-patched this manually across three builds); the AlphaPeptDeep adapter conversion is linearized (O(n^2) accumulation removed, 650k rows no longer stall); the psm table gains a File_Name uniqueness guard
- **Workstation test-report fix pack (v2.0.166)**: the master precheck (fingerprint + accession scan) honors `proteogenomics_annotated_fasta` with fasta fallback - a competition-library deployment with pg=1 no longer aborts at startup with a near-zero target count; the File_Name dedup moved from the never-executing precheck copy to the mandatory step-2 decoy-cleaning path, rewriting the cleaned files that feed the merge with the best-Q row kept (covers pg=0/1/2); the AlphaPeptDeep driver writes `predict.txt` directly via `--predict-out` (the 668k-row adapter re-entry measured 79 minutes becomes a passthrough; the R fallback is vectorized with verbatim %.5f pass-through - numerically identical doubles, 200k-sample verified; heartbeats go to stdout so they land in the master log); the MS2PIP adapter splits same-site double-modification paren tokens (`11,Carbamidomethyl[K](Gly[K])`), so the mappable primary modification no longer drops together with the unknown secondary
